# missions

課題パック。1パック1ディレクトリで、説明・初期データ・注入レシピ・対策候補・テスト・ヒント・解説を持つ（spec §11）。パックの開発用の固有テストと検証データは、各ディレクトリの `__tests__/` に置く（配布物には入らない。[作成ガイド](../docs/pack-authoring.md) §7）。

| パック | 種類 | 題材 |
| - | - | - |
| `onboarding/` | 練習（`tutorial`） | メモのタイトルの文字数制限が、保存する処理で確かめられていない。操作ガイドに沿って、体験する（再現）→ なおす（対策）→ たしかめる（検証）→ ふりかえる を 3 分で一周する |
| `idor/` | 課題（`mission`） | メモを ID 指定で取り出す処理が所有者を照合しない（IDOR、spec §8.1）。画面のリンクだけを隠す・すべて断る・所有者を照合するの 3 つの対策を試す |
| `stored-xss/` | 課題（`mission`） | 共有ページのコメントを HTML として描く（保存型 XSS、spec §8.2）。文字として表示する・script タグだけ消す・コメントを出さない、の 3 つの対策を試す。攻撃コメントは検証済みの固定ペイロードだけ |
| `sudo-misconfig/` | 課題（`mission`） | 運用担当に、管理者だけが行う保守の操作まで sudo で許可されている（設定ミスによる過剰な権限、CWE-269）。Linux 端末（ブラウザの中で動く本物の Linux）のターミナルで設定を点検し、不要な許可だけを外す。対策を選ぶのではなく、操作そのものが修正になる（`repair: record`） |
| `sqli/` | 課題（`mission`） | 検索語を SQL へ文字としてつなぐ（SQL インジェクション、spec §8.3）。語の禁止・検索の停止・値としてのバインドの 3 つの対策を試す。実行するのは SQLite |
| `unverified-update/` | 課題（`mission`） | 配布元から受け取った更新を root の権限で取り込むサーバで、取り込みのスクリプトから、ハッシュを確かめる行が外されたままになっている（完全性を確かめないコードの取り込み、CWE-494）。Linux 端末のターミナルで、`sha256sum` でハッシュを計算して配布元の一覧（`SHA256SUMS`）と見くらべ、更新を書き換えると値が変わることを確かめる。直すときは、スクリプトに、動かす前に `sha256sum -c` で確かめて、合わなければやめる行を入れる。確かめるだけでやめない・足された文字や行数を見て断るだけ・置き場を守るだけ・取り込みを止めるだけでは合格しない。操作そのものが修正になる（`repair: record`） |
| `postmessage-origin/` | 課題（`mission`） | 「スタンプを送る」画面が、届いたメッセージ（`postMessage`）の送り主を確かめずに使う（送信元を確かめない postMessage、CWE-346）。画面が埋め込んだ広告のページが、スタンプの部品と同じ形のメッセージを送ると、開いた人の名前でスタンプが書き込まれる。送り主の窓（`event.source`）を確かめる・オリジンが `"null"` かを確かめる・すべて捨てる、の 3 つの対策を試す。ページどうしは本物の別オリジンで、メッセージも本物 |
