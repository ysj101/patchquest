# PoC: Web Worker 上の PCRE2（WASM）と、処理の上限での打ち切り

Issue #238。入力チェックの正規表現が終わらなくなる問題（ReDoS、CWE-1333）を題材にする前提として、正規表現エンジン PCRE2 をブラウザの Worker で動かし、合否を経過時間ではなく**エンジンの処理の上限（match limit）に達したかどうか**で決められるかを確かめた。

## 結論

**採用する。** PCRE2 の公式のソース（10.49）から、自分で WebAssembly にビルドしたものを同梱する。npm の配布物は使わない。

- match limit を付けた照合は、上限に達すると `PCRE2_ERROR_MATCHLIMIT`（-47）を返して数ミリ秒〜0.2 秒で終わる。基盤のタイムアウト（テスト 1 件 5 秒で Worker ごと破棄）とは、戻り値で区別できる。
- 入れ子のくり返しを持つ正規表現は、PCRE2 の最適化（自動の possessive 化・開始位置の最適化）を有効にしたままでも、一致しない入力で処理量が 1 文字ごとに 2 倍になる。
- エンジンがパターンの項目を試すたびに呼ぶ関数（callout）で、回数と位置を取り出せる。これは「パターンの項目を試した回数」であり、後戻りの回数そのものではない。画面にもその名前で出す。

### ビルドしたもの

- `vendor/pcre2/pcre2.wasm`：**99,500 バイト**。SHA-256 `18dd1860037ffa03a7aba0e15796a72664043492c0fd0e7ed5b81e8b59a5678c`。
- 8 ビットのライブラリだけ。Unicode の表（`SUPPORT_UNICODE`）と JIT は入れていない。表示名の決まりは ASCII の範囲で、表を入れると大きさが数倍になる。
- **外の関数（import）が 0 個**。libc を持ち込まず、PCRE2 が使う関数（`memcpy`・`malloc` など）だけを `scripts/pcre2/libc.c` に持つ。通信や保存の手段を渡さずに動く。
- 公開する関数は `scripts/pcre2/wrapper.c` の 10 個（コンパイル・照合・回数・エラーの説明・版）。
- 同じ端末で 2 回ビルドして、同じハッシュになった。別の OS・別の版の clang で同じになるかは確かめていない。
- リポジトリに出来上がりを入れた。ビルドのたびに作らないのは、CI とビルドする人の環境に、wasm32 向けの clang とリンカを求めないため。差し替えは `tests/unit/pcre2-source.test.ts` がハッシュで止める。作り直す手順は [docs/pcre2-wasm.md](../pcre2-wasm.md)。

## 結果

### 処理の上限とエラーコード

正規表現 `^([a-z0-9]+[._-]?)*[a-z0-9]$`（入れ子のくり返し）と、同じ表示名を受け入れる `^[a-z0-9]+([._-][a-z0-9]+)*$`（入れ子なし）を、`a` を並べて最後だけ `!` にした入力と照合した。match limit は 1,000,000（PHP の `pcre.backtrack_limit` の既定値と同じ）。

| 入力の文字数 | 入れ子あり：試した回数 | 入れ子あり：結果 | 入れ子なし：試した回数 |
| - | - | - | - |
| 5 | 72 | 一致しない | 14 |
| 9 | 1,152 | 一致しない | 26 |
| 13 | 18,432 | 一致しない | 38 |
| 17 | 294,912 | 一致しない | 50 |
| 18 | 589,824 | 一致しない | 53 |
| 19 | 1,124,986 | **打ち切り（-47）** | 56 |
| 20 | 1,124,986 | **打ち切り（-47）** | 59 |

- 入れ子ありは、1 文字増えるたびに回数がちょうど 2 倍になる。入れ子なしは、1 文字につき 3 回ずつ増える。
- 打ち切りまでの時間は、Node で 0.05〜0.4 秒、Chrome の Worker では、打ち切り 5 件を含む検証（テスト 32 件）全体で 0.9 秒だった。
- match limit を 10,000,000（PCRE2 の既定値）にすると、20 文字の入力は一致しないという結論まで進む。上限は「結論が出る前に打ち切る」だけで、結果を変えない。
- 打ち切ったあとも、同じ実体で次の照合ができる。上限 10,000 で打ち切りを 2,000 回くり返したあと、モジュールのメモリは 1.1MB だった（照合のたびに確保した分を返している）。
- 「試した回数」（callout の回数）と match limit は、数え方が違う。上限 1,000,000 で打ち切られたとき、回数は 1,124,986 だった。画面では、回数を上限と比べる書き方をしない。

### 上限到達と、基盤のタイムアウトの区別

| 起きたこと | 分かり方 |
| - | - |
| エンジンが上限に達した | `pcre2_match` が -47 を返す。教材アプリは観測イベント `regex.match` に `outcome: 'limit'` を残し、応答 503 を返す。学習上の結果として扱う |
| 照合が終わらない（上限を付けない・大きすぎる） | 呼び出しが戻らない。アダプターが 5 秒で Worker を破棄し、`RuntimeError('timeout')` になる。基盤の失敗として扱い、不合格に数えない |

上限を付けない照合が実際に終わらないことは、同じ正規表現を V8 で動かして確かめた（下の「なぜ PCRE2 か」）。

### 最適化で問題が消えない組

- PCRE2 の既定の最適化を有効にしたままで、上の表の回数になった。callout を付けない照合（ふつうの使い方）でも、同じ入力で同じ戻り値（-1 か -47）になった。
- 最後の 1 文字を空白・英大文字・`..` に変えても、20 文字で打ち切られた。`x9x9…` のように文字を交互にしても同じ。
- `a.b.c.…` のように記号で区切った入力では、回数は増えない（81 回）。分け方が 1 通りに決まるため。
- 2 つの正規表現が同じ表示名を受け入れることは、5 種類の文字でできた 6 文字までのすべての文字列（19,531 通り）で確かめた（`missions/redos/__tests__/redos.test.ts`。PoC の時点では 7 文字まで、97,656 通り）。

### 処理の過程の取り出し

- `PCRE2_AUTO_CALLOUT` を付けてコンパイルすると、エンジンがパターンの項目を 1 つ試すたびに、登録した関数が呼ばれる。呼ばれた回数を数えられる。
- 関数には、パターンの中の位置と、入力の中の位置が渡る。`^([a-z0-9]+[._-]?)+$` と `aa!` で、`0@0 1@0 2@0 11@2 17@2 2@2 19@2 11@1 …`（パターンの位置@入力の位置）と、入力の位置が 2 → 1 と戻る様子が取れた。
- 製品では回数だけを使う。位置の記録は、PoC のあとで入口から外した（画面に出す使い道を決めていないものを、配布物に入れない）。

### なぜ PCRE2 か

同じ正規表現を Node（V8）の `RegExp` で動かすと、20 文字で 0.05 秒、24 文字で 0.5 秒、26 文字で 2.2 秒、28 文字で 9.6 秒かかった。途中で打ち切る上限を、外から指定する手段がない。V8 で合否を決めるには、経過時間を測るか Worker を破棄するしかなく、端末の速さで結果が変わる。PCRE2 は、上限に達したことをエンジン自身が戻り値で知らせるので、合否が端末の速さに左右されない。

PCRE2 は、PHP の `preg_match` などが使う実在のエンジンでもある。PHP は `pcre.backtrack_limit`（既定値 1000000）を `pcre2_set_match_limit` に渡し、`PCRE2_ERROR_MATCHLIMIT` を `PREG_BACKTRACK_LIMIT_ERROR` として知らせる（php-src の `ext/pcre/php_pcre.c` で確認）。

### Worker での初期化・破棄と作り直し・外部通信

製品ビルドを Chrome で開いて確かめた。

| 確認項目 | 結果 |
| - | - |
| 同梱ファイルからの読み込み | `pcre2.wasm` を Worker と同じディレクトリから取得。`Content-Type: application/wasm`、状態コード 200 |
| 通信・保存の API を塞ぐ前の初期化 | 取得は最初の準備の中で 1 回だけ行い、そのあとで `lockdown()` が `fetch` などを塞ぐ。塞いだあとの作り直し（初期状態へ戻す・テストごとの初期化）は、覚えておいた中身から行い、取得し直さない（`tests/unit/regex.test.ts`） |
| Worker の破棄と作り直し | 開始前チェック・検証・課題一覧へ戻って始め直す、の間に Worker が 7 回作られ、そのたびに `pcre2.wasm` を読み込んで動いた |
| 外部通信 | 配信元（`127.0.0.1:4238`）以外への要求は 0 件。コンソールとページのエラーも 0 件 |
| 待ち時間 | 課題を押してから開始前チェック（基準と注入後の検証を含む）が終わるまで 1.5 秒 |

## 実装への反映

- `runtimes/browser/regex.ts` の `RegexEngine` が、モジュールの読み込み・コンパイル・照合を受け持つ。照合の結果は `match`・`no-match`・`limit` の 3 つと、試した回数。
- 実行エンジン（`runtimes/browser/engine.ts`）は、アプリが `regex: { matchLimit }` を宣言していれば、準備のたびに新しい実体を作り、教材ロジックへ `ctx.regex` として渡す。配布物の読み込みは、演習用の機械と同じ手段（`AssetLoader`）を使う。
- 必要機能に `pcre2` を足した。
- 配布物には、版・ソースコードの入手先・ライセンスの全文を `assets/pcre2.LEGAL.txt` として添える。

## 確かめていないこと

- Chrome 以外のブラウザ。
- 別の OS・別の版の clang でビルドして、同じハッシュになるか。
- 上限を付けない照合で、アダプターのタイムアウト（Worker の破棄）が実際に働くこと。製品のコードは必ず上限を付けるので、この経路は通らない。タイムアウトそのものは、既存の E2E（`tests/e2e/runtime.spec.ts`）がテスト用のアプリで確かめている。
- 配布元以外への通信がないことは、Playwright の要求の記録で確かめた。OS の側でネットワークを切った状態では試していない。
